## 발견된 결함 (원작 catchtype 데모 4케이스 중 3개 불일치)
1. **'npm test도 돌려줘' → 'npm ㅅㄷㄴㅅ도'** : test+도(ㄷㅗ)가 붙은 6키 토큰 'testeh'에서
   en읽기 'testeh'(사전 무)와 ko읽기 'ㅅㄷㄴㅅ도'(stats 0.75) 충돌 → ko 승.
   원작은 en 'test' + ko '도'의 단어 내부 혼합 분할(mixed)로 풀어야 하나
   mixedSegments가 '완성 근거만' 요구해서 접두형 분할('test'는 dict-hit이지만
   '도'는 2키라 채택 안 됨... 검증 필요) — 분할 최소길이/경계 정책 재설계 필요.
2. **'Figma 링크 보내드릴게요' → '랴흠 링크'** : CamelCase 단어 'Figma'가 en사전에 없어
   (google-10000엔 소문자 figma만 존재할 수 있음) ko읽기 '랴흠'(stats)이 이김.
   대응: 대문자로 시작하는 CamelCase/고유명 보호 규칙 or hasPrefix로 접두 확인.
3. **'README에 설치' → 'READMEdp'** : 'README'는 fallback 통과(정상)지만 뒤 'dp'가
   ko '에'(dict, w0.983) vs en 'dp'(dict, w0.248) 충돌에서 4배 플립 임계(0.991)를
   0.008 미달로 아슬아슬하게 놓쳐 en 유지. 임계 완화(3배) 시 해결되나 오탐 리스크.
4. **'git' @ko → '햣'** : en사전에 git 없음(google-10000 누락) + ko stats가 이김.
   개발 용어(git, npm, ls)가 en사전에 부재 → 사전 증강 or 용어집 필요. npm은 jamo-run 폴백으로 'ㅞㅡ' 출력(부정확).
5. **'Q4'** : 숫자를 run에서 제거해 judgeWord에 들어가지 않으나 원작은 'Q4' 전체 유지.
   현재 구현은 'Q4'→'Q4' 정상 통과(Q는 acronym, 4는 숫자 passthrough)로 OK. (qa8의 크래시는 직접 호출 시에만, processText 경로엔 영향 없음)
