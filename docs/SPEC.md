# Catchtype 프로젝트 (가칭)

한/영 상태 잘못 둔 채 친 키를 치는 도중에 자동으로 고쳐주는 도구. 원작(catchtype.com)을 아이디어 참고용으로 삼되 **모두 새로 구현한다**.

## 아키텍처

```
packages/engine/    ← 핵심 판단 로직 (순수 TS, 의존성 없음)
packages/macos/     ← CGEventTap 쉘 (Swift) — 엔진을 임베드 후 후킹
packages/cli/       ← 터미널 테스트용 (엔진 검증)
packages/web/       ← 데모 페이지 (선택, 나중에)
```

## 엔진 사양 (v1)

### 입력
- 좌우변식(두벌식) 키 코드 시퀀스: `IOPcdEvent`에서 온 keycode 또는 브라우저 `event.code`
- 현재 언어 상태의 추정값 (`ko` | `en`, 시스템에서 얻지 못하면 마지막 확정값 유지)

### 판단 규칙 (실시간, 단어 단위)
- 키가 들어올 때마다 **en으로 읽은 문자열**과 **ko으로 읽은 문자열**을 동시 추적
- 어느 쪽이 실제로 "그 언어의 말이 되는"지 판단: 사전 히트 + 통계 점수(자모 빈도)
- 목표: 한 단어 안에서 언어 전환을 감지해 **앞 글자는 en, 뒷 글자는 ko** 같은 혼합 재조정 가능
- 현재 언어 상태는 확정된 판단을 따라 자동 갱신

### 우선순위 (v1 단순화)
"지금 상태의 언어로 말이 되면" 그대로 통과 → 아니면 상대 언어를 시도 → 둘 다 아니면 그대로 통과(사용자가 직접 친 게 아닐 가능성, 부호/숫자 등)

### 판단 자료
- 한국어 빈도 사전 (한→영 매핑 역산용이 아닌, "이게 한국어 단어인가" 판단용) — 한국어 어휘 목록을 출처와 함께 조사 후 포함
- 영어 사전 — 미국식 경량 wordlist
- 자판 매핑 테이블: 표준 두벌식 ↔ QWERTY 1:1 매핑(공개 표준, 직접 정의)

### 출력
- 변환 완료 문자열 (앱에 SEND 하는 형태) + 상태 변화 (`ko`/`en` 전환 신호 — macOS 앱은 이걸 이용해 시스템 입력 소스 전환)
- 판단에 사용된 근거 (사전히트 / 통계 / 통과) — 디버그용

## macOS 앱 요구사항

- Swift + CGEventTap (입력 감시 약 수정), Accessibility 권한 요청
- "비밀번호 필드"에서는 동작 안 함: `AXUIElement` 계층 확인 (원작 방식 — 개념 참고)
- sudo/SSH 비밀번호 프롬프트는 터미널 앱 이름으로 제외되도록 한 번 더 방어
- 백그라운드 상주, 최초 실행 Accessibility 권한 안내 얼럿
- 확정 문자열을 앱에 직접 SEND 하기 위해 `CGEvent` 키 이벤트 생성

## 테스트 전략

- 엔진:病例 단위 테스트 (dkssudgktpdy → 안녕하세요 / hello+한글 혼합 / 오탐 케이스 20개 이상)
- 통합: CLI로 전체 문장 시뮬레이션, 로칼 앱과 동일 인터페이스로 대조
- macOS는 맥북에서: Codex CLI에게 맡기고, 실제 타이핑 테스트는 소유자(사람)수행
